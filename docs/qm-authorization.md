# QM authorization interface

`POST /internal/qm/authorize` is a narrow service interface. It resolves an API key and evaluates existing team permissions in Superserve. It does not install authentication functions in another database or expose user/team tables. Nothing is added to sandbox startup or resume.

Configure `QM_AUTH_SERVICE_TOKEN` with a dedicated service credential of at least 32 characters, delivered through the existing secret deployment path in both regions. The caller sends it as `X-QM-Service-Token`, the end-user credential as `X-API-Key`, and JSON `{"action":"read"}`, `{"action":"write"}` or `{"action":"admin-link"}`. The service credential alone never authorizes team access. `read` uses `settings:read`; write/mint use `settings:write`. Key revocation and expiry are checked per request; the existing authorization service remains the role/membership authority. Console impersonation keys are denied.

A verified response contains `actor_type`, `actor_id`, `credential_id`, optional `user_id`, `team_id`, `owner_id`, `auth_outcome`, `attribution_status`, and `allowed`. Authorization denial returns HTTP 200 with `allowed:false`, preserving verified identity for the caller's public 403 log. Invalid end-user credentials return 401; missing service configuration or authority failures return 503. All responses are no-store. `owner_id` is storage provenance for the credential creator, not evidence of the human at the keyboard. API-key requests use the key ID as actor and leave user_id absent.

Human attribution requires an additional `X-QM-Human-Assertion`, signed by the trusted console session adapter. Configure its base64 Ed25519 public key in `QM_HUMAN_ASSERTION_PUBLIC_KEY`. JWT claims are issuer `console-auth-adapter`, audience `qm-management`, subject human UUID, issued-at and expiry no more than 60 seconds apart, plus `team_id`, `credential_id` and `action` bound to this request. Both key-owner and human permissions must allow the action. Caller-provided actor headers have no authority. The console issuer is a separate integration prerequisite; deploying this verifier does not establish a human producer or machine identity.

The endpoint strips sensitive headers and suppresses query values, dependency error text and request capture. The management caller must likewise omit bodies, credentials, assertion values and admin links from its logs. The service response carries only verified IDs and decisions, never keys or table records. Roll out the endpoint before enabling its consumer; without configuration it fails closed.
